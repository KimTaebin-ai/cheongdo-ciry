## 제품과 화면 원칙

제품명은 감좋은청년이다. 월세 일정·계좌 등록과 한전 전기요금 조회에 집중한다. 채팅에서 앱의 지원 기능을 선택·실행하며, 지원하지 않는 요청은 가능한 기능을 안내한다. 자유로운 표현을 받는 것과 모든 업무를 실행하는 것은 구분한다.

주황·검정·하양을 사용한다. 사용자 메시지는 회색 말풍선, AI 답변은 감 심볼과 짧은 문장으로 표현한다. 금액·일정·계좌 등 확인해야 할 값만 구조화 카드에 담는다. 반복되는 AI 이름과 대형 선택 버튼은 줄인다. 입력창은 하단에 고정한다. 캘린더는 사용자 요청에 따라 유지하는 내부 보조 뷰이며 외부 캘린더 연동을 의미하지 않는다.

## 버튼과 아이콘

- 모든 텍스트 행동 버튼과 전송 버튼은 주황색(#FF7A1A)으로 통일한다. 라벨과 아이콘은 검정색이다.
- 등록·조회·복사 등 행동의 차이는 버튼 폭·위치·아이콘으로 나타내고 색을 바꾸지 않는다.
- 송금정보 복사는 복사 아이콘, 외부 연결은 외부 이동 아이콘을 사용한다.
- 버튼 높이 44px, 모서리 12px, 라벨 13px Medium / 줄 높이 20px을 기본으로 한다. 원형 전송 버튼은 예외다.
- 아이콘과 라벨을 한 묶음으로 중앙 정렬하고 간격은 7px로 맞춘다.
- 감 심볼과 캘린더·알림·전송 아이콘의 크기와 선 두께를 맞춘다.
- 버튼 부연 설명을 반복하지 않고 출처·샘플·처리 상태는 별도 데이터로 표시한다.

## 월세 흐름

1. “월세 45만 원, 매달 8일로 등록해줘.”
2. 은행·계좌번호·예금주 등 빠진 정보를 채팅으로 질문한다.
3. 월세·반복일·수취인·계좌를 같은 대화에서 제시하고 등록 확인을 받는다. 시작월은 현재 월을 기본 제안하며 저장 전에 명확히 확인해야 한다.
4. 저장하고 동의한 기본 정책으로 자동 알림을 예약한다.
5. “월세 보낼 정보 알려줘”에 복사 가능한 송금 안내를 제공한다.
6. 복사와 실제 송금을 구분한다. 사용자는 은행 앱에서 직접 송금한다.

계좌번호는 문자열로 보존한다. 샘플 계좌·예금주는 합성 자료다. 초기 알림 동의는 온보딩에서 별도로 받고, 사전 동의가 없다면 임의로 예약하지 않는다. 상세 동의 화면은 이번 리파인 프로토타입에 포함하지 않았다.

## 전기요금 흐름

1. “전기요금도 챙겨줘” → 한전 연결 안내.
2. 공식 지원 경로의 동의·인증 후 연결한다. 실제 접근·인증·필드는 별도 검증 대상이다.
3. “전기요금 언제 내?” → 한전 MCP 조회 도구 → 금액·기한·상태·출처·조회 시각 카드.
4. 공식 납부 페이지로 연결한다. 결제수단 선택과 실제 결제·송금은 MVP 범위가 아니다.
5. 날짜가 검증되면 초기 동의한 정책으로 3일 전·1일 전 오전 9시 웹 내 알림을 예약한다.
6. 링크 방문으로 완료 처리하지 않는다. “납부했어” → 사용자 확인 → 기록 → 해당 월 알림 중지.

프로토타입의 한전 연결 버튼은 연결 확인 실패 화면으로, 샘플 체험은 샘플 조회 화면으로 연결한다. 실연동 성공을 가장하지 않는다.

## 나머지 요청의 기능 연결

| 사용자 요청 | 기능 연결 | 주의점 |
|---|---|---|
| 월세 금액·계좌 바꾸기 | 입력 파싱 → 누락 질문 → 확인 → 저장 | 타인 계좌를 추정하지 않음 |
| 월세 보낼 정보 | 저장한 설정 → 송금 안내 텍스트 | 복사와 송금 완료 분리 |
| 전기요금 조회 | 한전 도구 → 원본 필드 카드 | 임의 금액·날짜 생성 금지 |
| 알림 시각 변경 | 변경 전후 → 확인 → 적용 | 이전 알림 취소·재계산 |
| 알림 끄기 | 대상 확인 → 설정 변경 | 적용 결과를 대화에 표시 |
| 날짜별 보기 | 내부 청구 일정 → 캘린더 | 선택 날짜에서 청구 조회로 복귀 |
| 납부했어 | 청구 대상 확인 → 사용자 확인 기록 | 공급기관 검증과 구분 |
| 지원하지 않는 요청 | 가능한 기능·다음 행동 안내 | 실행 완료로 표현하지 않음 |

## 오류 분기

한전 미연결은 연결 안내, 자료 없음은 확인 불가, 조회 실패는 재시도·연결 확인으로 구분한다. 납부기한이 불확실하면 채팅으로 묻고 알림을 예약하지 않는다. 반복 조회·알림 중복은 내부 코드로 처리하며 별도 사용자용 중복 관리 화면은 만들지 않는다. 자동이체는 출금 예정이며 완료가 아니다.

## 평가 기준에 보여줄 증거

| 평가 항목 | 시연·측정 |
|---|---|
| 필수 기술 25% | Copilot SDK 모델 실행과 Agent Framework의 의도·문맥·도구 호출이 한 대화에서 연결 |
| 생산성 18% | 월세 등록·전기 조회의 시간, 수동 입력, 앱 탐색 단계 비교 |
| Azure 18% | 실제 배포 URL·로그·웹 알림 실행. 디자인만으로 충족하지 않음 |
| 완성도 16% | 등록→조회→복사/납부 연결→알림→확인의 정상·실패 흐름 |
| UX 12% | 채팅에서 의도를 말하고 카드로 확인·행동. 근거와 대기 상태 표시 |
| 신뢰 6% | 샘플 표시, 연결 실패 구분, 승인, 복사/방문과 완료 분리 |
| 독창성 5% | 독립생활의 반복 의무를 대화로 운영하는 일관된 경험 |

## 디자인 검증과 제한

최신 시안은 12개 상태와 주요 클릭 경로를 제공한다. 텍스트·프레임·아이콘은 편집 가능하다. 금액과 날짜는 합성 시연 데이터다. 자유 입력, 실제 인증, 클립보드 쓰기, 결제, 알림 발송은 프로토타입에서 실행하지 않는다. 캡처로 겹침·잘림을 검토하고 대화 영역이 입력창과 겹치지 않는지 좌표로 검사한다. 실제 키보드 접근성·반응형·스크린리더는 구현 단계에서 검증한다.

참고 조사와 적용 근거는 [UI 참고자료](UI-REFERENCES.md)에 기록한다.
