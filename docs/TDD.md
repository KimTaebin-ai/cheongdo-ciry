# TDD — 120분 MVP의 선택과 이유

- Technical Decision Document / 2026-11-05 / 구현 전 결정안.
- 목적: PRD, 구현 방향: TRD. 기존 확대 계획을 아래 결정으로 대체한다.

## D01. 한전과 수동 월세에 집중

3명이 120분 안에 모든 공과금과 금융 서비스를 붙일 수 있다고 가정하지 않는다. 한전은 공식 조회·납부 페이지 연결을, 월세는 사용자 입력에서 반복 관리를 만드는 가치를 보여준다. 가스·보험은 후속이며 초기에는 지원 버튼도 만들지 않는다.

## D02. 채팅으로 입력하고 바로 보여주기

에이전트가 자료와 요청을 이해하고 필요한 도구를 호출해 금액·날짜 카드와 송금 안내 텍스트를 보여준다. 별도 내용 확인 화면과 월간 요약은 핵심 과제의 완료에 필수적이지 않아 제외한다. 월세 입력 확인은 대화 안에서 수행하고, 불확실한 값도 채팅으로 묻는다.

## D03. 중복 관리를 사용자 기능에서 제거

사용자가 중복 고지서를 병합하거나 검토하는 기능은 만들지 않는다. 다만 동일 청구 재조회와 알림 재시도가 중복 청구·알림을 만들면 핵심 경험이 깨진다. ID 기반 갱신과 알림 키는 내부 코드로 유지한다. 이 보장을 모델의 판단에만 맡기지 않는다.

## D04. 에이전트는 의도·문맥, 코드는 정확한 기록

'전기세 언제 내?'에서 도구를 고르고, 월세 등록의 누락을 묻는 부분은 에이전트가 맡는다. 금액·날짜 검증, 카드 필드, 저장, 알림 시점은 코드로 결정한다. 에이전트에 모든 것을 맡긴다는 이유로 없는 청구를 생성하거나 시각 계산을 추측하지 않는다.

## D05. Agent Framework + Copilot SDK의 한 흐름

두 필수 기술을 한 실행 경로에서 사용한다. Agent Framework로 흐름과 도구를 연결하고 Copilot SDK로 모델을 실행한다. 앱에 직접 등록한 청구 조회 MCP 도구를 후보로 둔다. 시간 내 통합 실패 시 함수 도구 대체와 MCP 미완료를 공개한다. 별도 다중 에이전트나 범용 MCP 플랫폼은 만들지 않는다.

## D06. 한전은 공식 링크로 연결

사용자는 원격 브라우저 자동화 검증을 중단하고 한전ON 연결만 하기로 결정했다. 인증 화면 진입·수단 선택은 확인했지만 실제 승인 후 조회, 원격 서비스의 화면 인계, 모바일 납부는 검증하지 못했다. 해당 서비스 계정도 없어 이 구성을 MVP의 필수 경로로 두지 않는다. 앱의 한전 버튼으로 공식 페이지를 열고 사용자가 직접 인증·납부한다. 금액·기한은 필요할 때 직접 등록한다.

## D07. 월세는 직접 등록, 송금 텍스트만

사용자가 금액·납부일·은행·계좌번호·예금주를 입력하면 재사용할 수 있다. 계약서 OCR과 금융 API가 필요 없어 일정 내 구현에 적합하다. 앱은 복사 가능한 정보를 제공하고 사용자는 은행 앱에서 송금한다. 복사를 납부 완료로 오인하지 않는다.

## D08. 처음 날짜를 얻으면 자동 예약

사용자가 매번 알림을 명령해야 하면 기억 부담이 남는다. 초기 동의 후 기본 정책으로 자동 예약하고 변경/해제를 제공한다. 3일 전·1일 전 오전 9시는 초기 기본값이며 사용자가 바꿀 수 있다. 웹 내 알림으로 범위를 줄여 브라우저 종료 중 푸시는 제공하지 않는다.

## D09. 단일 컨테이너와 단순 저장

프런트 정적 빌드와 백엔드를 한 컨테이너로 Azure에 배포해 별도 호스팅과 CORS 구성을 줄인다. SQLite와 단일 replica로 시작한다. 영속 볼륨 미구성 시 데이터 유실 가능성을 명시하고 상용 준비 완료라고 하지 않는다. 관리형 DB·별도 작업 서비스는 후속으로 미룬다.

## D10. 3명 분업과 마감 통합

A(사용자)는 모바일 UI/시연, B는 AI/API, C는 어댑터/저장/알림/배포를 담당한다. C의 과부하를 줄이기 위해 한전은 링크만, 알림은 웹 내부, 배포는 단일 컨테이너로 제한한다. 공통 계약은 10분에 확정하고 샘플로 병렬 개발한다. 90분 이후는 통합과 검증에만 쓴다.

## D11. 신뢰와 평가 증거를 핵심 흐름에 포함

조회 출처·조회 시각·샘플 여부를 표시하고, 미확인을 미납으로 확정하지 않는다. 비밀은 서버에 보관하고 데모 접근을 제한한다. 실제 송금은 없다. 시간 절감 비교, SDK 도구 실행, Azure URL, 알림 시연을 평가 증거로 남긴다. 부족한 연동과 영속성은 숨기지 않는다.

## 재검토 시점

15분에 SDK 인증과 Azure 권한을 판정하고 막힌 항목을 공유한다. 55분에 핵심 로컬 흐름, 90분에 배포 통합을 확인한다. 이후 추가 기관·관리형 저장소·백그라운드 알림은 대회 이후 범위로 재검토한다.

## D12. 모바일 우선 웹앱

휴대폰에서 바로 접속하도록 반응형 웹을 Azure에 배포한다. 네이티브 앱스토어 출시와 PC 확장 설치는 요구하지 않는다. 모바일 인증 앱과 한전ON의 외부 이동을 전제로 설계하며, 앱이 다른 출처의 세션을 자동 공유한다고 가정하지 않는다.

## D13. 기존 함수 도구를 앱 MCP 서버로 묶는다

사용자는 앱 기능을 MCP 서버로 묶어 에이전트가 자연스럽게 실행하도록 요청했다. 원격 main 8dc0e32에는 make_tools로 등록된 함수 5개가 있으므로 업무 로직을 재사용하고 MCP 전송·스키마 계층을 덧붙인다. 도구 이름을 바꾸는 것만으로 MCP 연결이 완료되지는 않는다. 변경·완료·월세 계좌·반복 설정은 기존 함수와의 기능 차이를 확인해 추가한다.

프런트/백엔드 SSE와 Bill 스키마가 달라 계약 정규화를 MCP 도입과 함께 수행한다. SDK 연결만 있고 알림 발송·승인 검증이 없는 상태를 완성으로 오인하지 않는다. 이미지 해석은 모델 입력의 역할로 두되 현재 미지원 입력 경로를 별도로 검증한다.
