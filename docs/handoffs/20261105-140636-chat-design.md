AGENTS/PRD/TRD/TDD, 공급기관 연동 조사 및 기존 핸드오프를 읽고 채팅 중심으로 앱을 다시 디자인했다. 사용자의 최신 요청인 무채색 및 버튼 부연 설명 제거를 유지했다.

- 새 페이지: `02 · 채팅 중심 워크플로우` (`6:2`). 이전 시안 페이지는 보존했다.

- 상태 10개: 처음 연결(6:3), 오늘의 대화(6:4), 청구 조회(6:5), 채팅 내 납부 선택(6:6), 납부 확인(6:7), 알림 변경(6:8), 날짜별 보기(6:9), 연결 만료(6:10), 납부 기록 완료(9:32), 알림 변경 완료(9:82).

- 변경 파일: `docs/design/WORKFLOW.md`, 이 핸드오프. PRD/TRD/TDD와 API 계약은 변경하지 않았다.

## 핵심 결정

채팅을 홈으로 사용하고 별도 하단 탭을 제거했다. 캘린더도 대화 속 카드로 표시한다. 최초 알림 동의 후 검증된 납부일에서 기본 알림을 자동 예약한다. 알림 변경은 제안·확인·반영으로 구분한다. 자동이체와 완료를 혼동하지 않으며 납부 기록은 사용자 확인 근거로 표현한다. 서비스명은 가칭, 모든 화면 데이터는 합성 시연임을 표시한다.

## 검증

- Figma에서 10개 화면 및 워크플로우 보드를 캡처해 시각 검토했다. 완료 상태 두 화면도 별도 검토했다.
- 도구 결과에서 화면 10개, 링크 41개, 편집 가능한 텍스트 251개, 화면 placeholder 0개를 확인했다.
- 문서는 UTF-8, 로컬 링크, 코드 펜스·줄 끝 공백을 종료 전 검사한다. 결과는 실행 출력 기준으로 확인한다.
- 실제 앱·인증·공급기관 연결·결제·알림 발송·키보드 접근성은 테스트하지 않았다.

## 제한과 미완료

- 고정된 예시 상태를 연결한 디자인 프로토타입이다. 자유 입력·모든 날짜 선택·실제 납부 링크 이동은 구현되지 않았다.
- 업로드 검토, 중복, 월세 등록 상세, 전체 월간 요약의 세부 화면은 후속 디자인 범위다. 워크플로우 문서에 동작을 명세했다.
- 공용 버튼 라이브러리 가져오기는 이전 디자인 작업에서 응답 크기 제한으로 실패했다. 현재 시안은 편집 가능한 텍스트·프레임·벡터로 구성되어 있으며 라이브러리 컴포넌트화는 미완료다.
- 연동 지원은 미검증. 실제 서비스 지원 범위를 과장하지 않는다.
